# British Airways Data Science

Two data-science deliverables from the British Airways Forage virtual
experience: a **lounge-demand forecasting model** for Heathrow Terminal 3
(Task 1) and an **end-to-end machine-learning pipeline** that predicts
customer booking behaviour (Task 2).

Built with **pandas / NumPy** for data wrangling, **scikit-learn** for model
training and tuning, and **Matplotlib / Seaborn** for exploratory analysis and
visualisation.

## Project Overview

**Task 1 — Premium Lounge Modeling.** A predictive framework that forecasts
passenger demand for the premium lounges (Concorde Room, First, Club) so
British Airways can plan daily capacity across 1500+ scheduled departures.
Flights are grouped into high-level buckets (Long-haul vs Short-haul and
Time-of-Day), and a reusable lookup table converts seat capacity into expected
lounge-eligible passenger volumes — without relying on individual booking data.

**Task 2 — Booking Behaviour Prediction.** An end-to-end scikit-learn pipeline
that classifies whether a customer booking will be completed. It processes a
50,000 × 14 booking sample through cleaning, EDA, feature engineering and model
selection, identifying `purchase_lead` as the strongest driver and reaching
**85% model accuracy** with a tuned Random Forest.

## How Task 1 Works (Lounge Eligibility)

- **Input.** The British Airways Summer Schedule
  (`spreadsheets/British_Airways_Summer_Schedule_Dataset-Forage_Data_Science_Task1.xlsx`),
  listing 1500+ scheduled departures with their cabin capacities.
- **Grouping.** Flights are bucketed by Long-haul vs Short-haul and
  Time-of-Day so eligibility can be estimated for a full schedule without
  per-passenger booking records.
- **Capacity & percentages.** Total capacity = First + Business + Economy
  seats. Each group’s eligibility percentage is the number of eligible
  passengers divided by total seat capacity for that group.
- **Output.** A reusable lookup table plus a written justification of the
  modeling decisions (`spreadsheets/answers/Lounge_Eligibility_Lookup_Table.xlsx`).
  The flight-agnostic design means the same table applies to future or unknown
  schedules.

## How Task 2 Works (Booking-Behaviour Pipeline)

`src/main.py` runs six stages over the customer booking data:

1. **Load & clean** — `data_loader.py` reads the 50,000 × 14 dataset (with an
   ISO-8859-1 encoding fallback) and drops the 719 duplicate rows found in EDA.
2. **Exploratory data analysis** — `visualizer.py` plots the target
   distribution, histograms, correlation heatmap and booking completion by
   flight day.
3. **Feature engineering** — `preprocessing.py` maps `flight_day` to numbers,
   frequency-encodes the high-cardinality `route` and `booking_origin`,
   one-hot encodes `sales_channel` and `trip_type`, then standard-scales.
4. **Model comparison** — `model_engine.py` benchmarks 7 classifiers and ranks
   them by accuracy.
5. **Hyperparameter tuning** — GridSearchCV targets the Random Forest
   (`n_estimators` 50/100, `max_depth` 10/20/None, `min_samples_split` 2/5,
   3-fold cross-validation, `f1` scoring).
6. **Evaluation** — a final classification report, confusion matrix and
   top-15 feature-importance plot.

Seven classifiers were benchmarked on the held-out 20% test split; the tuned
Random Forest was selected as the final model.

| Model                | Accuracy | Precision | Recall | F1 Score | ROC AUC |
|----------------------|----------|-----------|--------|----------|---------|
| Random Forest        | 0.8528   | 0.549180  | 0.089572 | 0.154023 | 0.769455 |
| Gradient Boosting    | 0.8523   | 0.611765  | 0.034759 | 0.065781 | 0.772392 |
| AdaBoost             | 0.8507   | 0.548387  | 0.011364 | 0.022266 | 0.750238 |
| Logistic Regression  | 0.8504   | 0.000000  | 0.000000 | 0.000000 | 0.681787 |
| K-Nearest Neighbors  | 0.8348   | 0.356089  | 0.129011 | 0.189401 | 0.637912 |
| Decision Tree        | 0.7793   | 0.281500  | 0.306150 | 0.293308 | 0.584302 |
| Naive Bayes          | 0.6778   | 0.245878  | 0.558155 | 0.341374 | 0.681815 |

**Top predictors:** `purchase_lead` (0.1931), `route_freq` (0.1473),
`flight_hour` (0.1434), `length_of_stay` (0.1283), `booking_origin_freq`
(0.1131).

## Error Handling & Robustness

| Situation                     | Behaviour                                                   |
|-------------------------------|-------------------------------------------------------------|
| File encoding issues          | `data_loader.py` tries ISO-8859-1, then falls back to the default encoding |
| Duplicate rows in the data    | Dropped at load time, with the number removed logged        |
| High-cardinality categoricals | Frequency-encoded to keep feature dimensionality low        |
| Class imbalance               | Train/test split is stratified; tuning uses `f1` scoring    |
| Missing dependencies          | `pip install -r requirements.txt` covers the full stack     |

## Limitations

- **Accuracy is inflated by class imbalance.** The tuned Random Forest reaches
  85% accuracy but has only ~0.09 recall on the minority
  `booking_complete = 1` class; most real bookings in the test set are still
  missed.
- **Static sample data.** All results come from the single 50,000-row sample;
  the Task 1 percentages are derived purely from that one summer schedule, not
  from live or rolling booking feeds.
- **Baseline models highlight the imbalance.** Logistic Regression and AdaBoost
  effectively predict the majority class (precision/recall near 0 on the
  positive class).
- **Task 1 is an estimate.** Lookup-table percentages are seat-capacity ratios
  with stated assumptions, not measured passenger counts per lounge.

## Possible Improvements

- Treat class imbalance explicitly (SMOTE / `class_weight` / decision-threshold
  tuning) to lift minority-class recall.
- Add stronger models (XGBoost, LightGBM) and broader hyperparameter searches.
- Persist the tuned model (`joblib`/`pickle`) and track experiments (MLflow).
- Refresh the Task 1 lookup table automatically from future flying schedules
  or live booking feeds.
- Analyse `purchase_lead` windows by route and market for targeted marketing.
- Add time-series modelling of daily lounge demand for capacity planning.
